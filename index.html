03 / Registered finding

Keeping evidence through handoffs helped. One bounded correction helped more.

Five reconstructed decision moments were answered eight times with each method. Every answer was graded against rules written before the run.

0/40Plain written notesNo answer passed every prewritten check.
17/40Evidence tableThis method required source-linked claims and named unknowns; 17 answers met every rule.
34/40Table + one correctionOne exact message named the broken rule.

The honest verdict

The evidence-table claim failed one registered constraint rule. The bounded-feedback claim passed its narrower rules.

This measures communication, traceability, and rule-following in the exercise. It does not prove better real-world judgment or lives saved.

04 / Continue the work

An AI harness can orient itself and verify the package without private infrastructure.

The package contains no VPN or GPU credentials, no remote launcher, and no old six-candidate gallery. This handoff can replay and verify the recorded run. It cannot launch a new agent or GPU run because the private run-preparation control and remote execution endpoint are not included.

$ npm ci
$ npm run verify
$ npm run dev

open http://localhost:5184

Tell the harness to do this first

  1. Read AGENTS.md and README.md in the repository root.
  2. Run the package verification before editing.
  3. Keep real records, simulated decisions, and later analysis separate.
  4. After a visible change, run the browser test and inspect both screenshots.

Official source details, hashes, transformations, and attribution are in product/disaster-replay/DATA-SOURCES.md. The frozen experimental verdict and limits are in experiment/PRODUCTION-RESULTS.md.
